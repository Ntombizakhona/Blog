
Accepting Z Supremacy
=====================

_“Wait… is AWS Organizations the same as AWS Organisations?”_
-------------------------------------------------------------


> **“Wait… is AWS Organizations the same as AWS Organisations?”**

That was the question I was asked recently.

I know, random…

But, the short answer? **Yes.**

The longer answer is a reminder that, in technology, **the spelling chosen by the product creator wins.**

As South Africans (and much of the Commonwealth), we naturally write **organisation**, **optimisation**, **authorisation**, **virtualisation**, and many other words with an **“s”**.

Then we enter the world of cloud computing and suddenly we’re greeted with **Z Supremacy.**

It’s all American English.

The Product Name Is the Product Name
------------------------------------

When you’re referring to an AWS service, Microsoft feature, Google Cloud product, or any other technology, you’re no longer just writing English.

You’re referring to a **named product**.

That means the official spelling matters.

For example:

✅ AWS Organizations
❌ AWS Organisations

Even though **organisations** is perfectly correct English in South Africa, it isn’t the name of the AWS service.

It’s no different from writing:

*   GitHub instead of Github
*   Kubernetes instead of Kubernetees
*   JavaScript instead of Javascript

The branding is part of the identity.

Documentation Should Match Reality
----------------------------------

Imagine someone searches for:

> _“AWS Organisations SCP”_

They’ll probably still find what they’re need.

But every AWS document, certification exam, CLI command, console screenshot, and official tutorial uses:

> **_AWS Organizations_**

Matching the official terminology makes your documentation:

*   easier to search
*   easier to verify
*   easier for beginners to follow
*   consistent with certification material

**Consistency reduces confusion.**

My Rule
-------

When I’m writing generally, I happily use South African English.

*   organisation
*   optimisation
*   initialise
*   authorised

But the moment I’m talking about a product, API, service, or command, I switch to whatever spelling the creator chose.

If AWS says **Organizations**, then it’s **Organizations**.

If Microsoft names a feature a certain way, I use that exact name.

If Google Cloud brands something with American spelling, I follow the branding.

Not because one version of English is “better,” but because **precision matters more than preference in technical writing.**

Accepting Z Supremacy
---------------------

I’ve come to accept what I jokingly call **Z Supremacy**.

Not because my South African keyboard suddenly became American.

Not because I stopped believing **organisation** is the correct spelling where I live.

But because technology has a global language, and much of that language was created by American companies.

When writing about their products, I’m borrowing _their_ vocabulary not replacing my own.

So yes…

I still write **organisation** in everyday life.

But when AWS is involved?

Long live **Organizations**.
